# Workflow

This document describes the complete GEO Engine runtime workflow from research setup to history tracking.

## High-Level Flow

```mermaid
flowchart TD
    P[Select Property] --> A[Website Audit]
    P --> F[FAQ / Platform Discovery]
    A --> C[Content Generation]
    F --> C
    C --> Q[Publishing Queue]
    Q --> PA[Local Publisher Agent]
    PA --> B[Playwright Browser]
    B --> HR[Human Review]
    HR --> H[History]
    C --> CT[Citation Test]
    CT --> H
    A --> H
    F --> H
```

## Property Context

Every workflow starts with a selected Property. The Property provides:

- name;
- brand name;
- domain;
- description;
- `property_id` for database scoping.

All pages should operate only on the active Property.

## Website Audit

```mermaid
sequenceDiagram
    participant UI as Frontend Website Audit
    participant API as FastAPI Backend
    participant DB as PostgreSQL
    participant S as Website Audit Services

    UI->>API: POST /api/v1/audit/run
    API->>S: crawl + extract + analyze + score
    S->>DB: website_audits
    S->>DB: website_pages
    S->>DB: website_audit_recommendations
    API->>DB: history_events
    API-->>UI: audit result
```

The audit stores pages, score components, brand understanding, missing pages, missing topics, internal link suggestions, FAQ opportunities, and content recommendations.

## FAQ and Platform Discovery

### AI FAQ

```mermaid
flowchart LR
    Topic[Category / Topic] --> LLM[AI FAQ Service]
    LLM --> FS[faq_sets]
    FS --> F[faqs]
    F --> UI[AI FAQ Panel]
```

AI FAQ is generated by the LLM and stored in `faq_sets` and `faqs`.

### Reddit Platform FAQ

```mermaid
flowchart LR
    Topic --> RR[Reddit Retriever]
    RR --> PQ[platform_questions]
    PQ --> FAQ[Platform FAQ Generation]
    FAQ --> FS[faq_sets]
    FS --> UI[Platform FAQ Panel]
```

Reddit naturally provides question/discussion style data, so the UI displays platform FAQs.

### Xiaohongshu Trending Posts

```mermaid
sequenceDiagram
    participant UI as Frontend
    participant API as Backend
    participant DB as PostgreSQL
    participant RA as retriever_agent.py
    participant PW as Playwright Chrome
    participant XHS as Rednote Web

    UI->>API: GET /content/faqs?mode=platform&publish_platform=xiaohongshu
    API->>DB: create retrieval task
    API-->>UI: status=retrieving
    RA->>API: poll pending retrieval task
    RA->>PW: launch web profile
    PW->>XHS: search topic and open notes
    RA->>API: complete task with retrieved posts
    API->>DB: platform_questions
    UI->>API: poll/refresh posts
    API-->>UI: Trending Posts
```

Xiaohongshu does not convert retrieved posts into FAQ for the current product behavior. It displays platform posts directly and uses them as grounding for Xiaohongshu-native content.

## Content Generation

```mermaid
flowchart TD
    Source[AI FAQ / Reddit FAQ / Xiaohongshu Posts] --> G[Content Generator]
    G --> C[contents]
    C --> H[history_events]
```

Generated content is stored in `contents`. Publishing must not overwrite generated content. Platform-specific formatting is stored on publishing jobs.

## Publishing Queue

```mermaid
sequenceDiagram
    participant UI as Frontend
    participant API as Backend
    participant DB as PostgreSQL
    participant PA as publisher_agent.py
    participant P as Platform Publisher
    participant PW as Playwright

    UI->>API: POST /api/v1/publishing/publish/{content_id}
    API->>DB: create publishing_jobs status=queued
    API->>DB: store formatted_title/formatted_body
    PA->>API: GET /api/v1/publishing/pending
    API->>DB: claim job queued -> processing
    API-->>PA: task payload
    PA->>P: get platform publisher
    P->>PW: open local browser profile
    PW-->>PA: Review Ready
    PA->>API: POST /publishing/complete status=review_ready
    API->>DB: update job + history
```

The queue is consumed by a local publisher agent, not by Render.

## Human Review Mode

Publishing prepares the platform page and stops:

```text
Open platform
Fill title
Fill body
Capture screenshot
Print READY_FOR_REVIEW
Wait for terminal ENTER
```

The human decides whether to edit, publish, save draft, or close the page.

## Citation Tests

```mermaid
flowchart LR
    Prompt --> Model[Selected LLM]
    Model --> Result[citation_test_runs / citation_test_results]
    Result --> History[history_events]
```

Citation tests store prompt, model, mentioned status, rank, response snippet, raw response, and timestamps.

## History

History records major events:

- FAQ Generated
- Content Generated
- Website Audit
- Publish Requested
- Review Ready
- Published
- Publish Failed
- Citation Test Started
- Citation Test Finished

History is the research audit trail. It should let a researcher reconstruct what was generated, retrieved, queued, tested, and reviewed for each Property.

## End-to-End Research Workflow

```text
1. Select Property
2. Run Website Audit
3. Generate AI FAQ
4. Generate Reddit Platform FAQ or Xiaohongshu Trending Posts
5. Generate content
6. Queue publish job
7. Run local publisher agent
8. Review prepared browser page
9. Run citation test
10. Inspect History
```
